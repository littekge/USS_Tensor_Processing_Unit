# Compilation Flow

This project is intentionally educational. The goal is to show the shape of a typical MLIR lowering pipeline without hiding the steps behind an aggressive optimization pipeline.

## Stage 1: StableHLO-lite input

The input is a textual `.mlir` file that uses StableHLO-style operations. The included sample, `Tiny_NN_Recent.mlir` (workspace root: `Tiny_NN_Recent.mlir`), contains a small neural-network-shaped computation with:

- `stablehlo.transpose`
- `stablehlo.broadcast_in_dim`
- `stablehlo.multiply`
- `stablehlo.dot_general`
- `stablehlo.add`

Because the system MLIR packages do not ship StableHLO, the project parses these operations as unregistered ops and handles the supported subset manually.


## Stage 2: StableHLO-lite to `myhw`

The first C++ lowering pass rewrites the input into a tiny custom dialect named `myhw`.

Files involved:
- The lowering implementation: `lib/Conversion/MyHWToLLVM.cpp` (C++ lowering helpers live here).
- The lowering driver/binary is built from: `tools/mlir-educational-example.cpp` and linked into the binary `build/bin/mlir-educational-example` by the top-level `CMakeLists.txt`.

Why this exists:

- It shows how a custom dialect fits into a compiler pipeline.
- It isolates the semantics of the high-level model from the mechanics of the MLIR parser.
- It keeps the example readable because the dialect is intentionally small.

The dialect contains a handful of operations that map directly to the operations used in the sample network:

- `myhw.transpose`
- `myhw.broadcast`
- `myhw.elementwise`
- `myhw.matmul`


## Stage 3: `myhw` to loops and memory

The second pass lowers `myhw` into standard MLIR operations. In this example the transformation is implemented in the same lowering code (see `lib/Conversion/MyHWToLLVM.cpp`) and the Python driver writes an intermediate normalized MLIR to `<work-dir>/normalized_input.mlir` before invoking the lowering binary.

The lowered operations include:

- `memref.alloc`
- `memref.load`
- `memref.store`
- `arith.addf`
- `arith.mulf`

This is the point where the model stops looking like a neural-network IR and starts looking like ordinary imperative code. The current lowering is intentionally straight-line and unrolled for the sample network, which makes the data movement and compute order easy to inspect without adding loop machinery.


## Stage 4: LLVM dialect lowering

Once the module consists of standard arithmetic, function, and memref operations, the tool runs the usual MLIR lowering passes. The driver script `scripts/compile_pipeline.py` invokes the lowering binary and writes the LLVM-dialect MLIR to `<work-dir>/lowered_to_llvm.mlir`.

Passes run (examples):

- `arith` to `llvm`
- `func` to `llvm`
- `memref` to `llvm`
- reconcile unrealized casts

The output of this stage is the final LLVM dialect `.mlir` file.

## Stage 5: Executable generation

If the Python driver is run with `--emit-executable`, it performs the final steps to produce a runnable program. `scripts/compile_pipeline.py` uses these workspace-relative file locations:

- Normalized MLIR: `<work-dir>/normalized_input.mlir`
- LLVM dialect MLIR: `<work-dir>/lowered_to_llvm.mlir`
- LLVM IR: `<work-dir>/lowered.ll`
- Object file: `<work-dir>/lowered.o`
- Host wrapper (C++): `<work-dir>/host_main.cpp` (generated by the driver)
- Final executable: `<work-dir>/tiny_nn_demo`

Commands used (examples invoked by the driver):
- `mlir-translate-19 --mlir-to-llvmir <work-dir>/lowered_to_llvm.mlir -o <work-dir>/lowered.ll`
- `llc-19 <work-dir>/lowered.ll -filetype=obj -o <work-dir>/lowered.o`
- `clang++-19 <work-dir>/host_main.cpp <work-dir>/lowered.o -o <work-dir>/tiny_nn_demo` (includes `-I/usr/lib/llvm-19/include -L/usr/lib/llvm-19/lib` in the driver)

The generated executable lives in the chosen working directory.

## Why this ordering

The pipeline is not tuned for performance. It is arranged to make each transition easy to understand:

1. High-level tensor-like operations
2. A custom dialect with straightforward semantics
3. Imperative loops and explicit memory
4. LLVM dialect
5. LLVM IR and an executable

That order mirrors how many MLIR pipelines are explained in practice.
